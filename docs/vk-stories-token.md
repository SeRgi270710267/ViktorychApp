# VK user token for stories

The usual path is the spare account's web session: [vk-session.md](vk-session.md). This page is the alternative when `VK_LOGIN` and `VK_SESSION` are both unset.

Checked against VK’s own pages on 21 Oct 2026. This sync reads `VK_USER_TOKEN` only inside the Refresh feeds step. It is masked, never printed, and never committed. Leave it unset and VK stories stay off. The sync calls `stories.get` and `stories.getById` only. It does not post, delete, or mark stories seen.

1. Sign in to the VK ID authorization service with your own VK account and create a business profile. Creating an app requires VK Business ID. Standalone app settings on dev.vk.com are no longer available; VK moved those apps to VK ID. Official page: https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/create-application

2. In that cabinet open **Мои приложения**, click **Добавить приложение**, name it, choose platform **Web**, and set a base domain you control plus a trusted redirect URL. The redirect domain must exactly match the base domain, including case. Click **Создать приложение**. During creation, click **Подтвердить** on «Подтвердите профиль» so settings, keys, and support stay available. VK blocks the app when the business profile is not confirmed: accounts registered before 15 December 2025 had until 1 March 2026; accounts registered after that date are blocked 60 days after the first app. VK also blocks an app for an offer violation, a VK ID button that breaks their visual rules, or domains that do not match the app settings.

3. Do not use a third-party token site. The VK ID scope list is only `vkid.personal_info`, `email`, and `phone` (https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/work-with-user-info/scopes). `stories` is not on it. `stories.get` says the stories right “is issued in exceptional cases by a request to support at devsupport@corp.vk.com” (https://dev.vk.com/en/stories.get). Write to that address from this app and ask for the stories right for your own account. VK’s user-info page says the same about other extended rights such as friends, video, and photos.

4. After VK grants that right and it is allowed on the app, authorize yourself with VK ID’s authorization-code flow and PKCE. Official page: https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/start-integration/auth-without-sdk/auth-without-sdk-web
   - Generate a `code_verifier` of 43–128 characters from `a-z`, `A-Z`, `0-9`, `_`, `-`. `code_challenge` is `BASE64URL-ENCODE(SHA256(ASCII(code_verifier)))` and `code_challenge_method` is `S256`.
   - `state` is at least 32 characters from that same set. VK returns it unchanged; if it differs, discard the answer.
   - Open `https://id.vk.ru/authorize?response_type=code&client_id=YOUR_APP_ID&redirect_uri=YOUR_TRUSTED_REDIRECT&state=STATE&code_challenge=CHALLENGE&code_challenge_method=S256&scope=stories`
   - The redirect page must not contain scripts or embedded content (images, styles, counters). The code lives 10 minutes and arrives with `device_id`. Passing `scope=stories` before the app is allowed to request it returns `invalid_scope`.
   - Exchange it with `POST https://id.vk.ru/oauth2/auth`, `Content-Type: application/x-www-form-urlencoded`, body `grant_type=authorization_code`, `code_verifier`, `redirect_uri`, `code`, `client_id`, `device_id`, and `state`. The `access_token` in that JSON is the secret value. A confidential app must also send `service_token`, and VK rejects the exchange unless it comes from an IP you listed.

5. What VK itself states about expiry and blocking:
   - A new VK ID access token lasts 1 hour. After that VK treats it as invalid (https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/tokens/access-token). The refresh token lasts 180 days. `POST https://id.vk.ru/oauth2/auth` with `grant_type=refresh_token` returns a new pair and invalidates the previous pair. Reusing the old refresh token invalidates the whole session. This sync does not refresh tokens, so the next run after that hour gets error 5 and opens or updates the existing “Sync problem” issue.
   - The old `offline` right (bit +65536) sets `expires_in` to 0, so that key does not expire. VK’s access-rights page says it “is not used in the Open API” (https://dev.vk.com/en/reference/access-rights). It is not in the VK ID scope list, so a new VK ID token is not an offline token.
   - Implicit Flow and Authorization Code Flow for user keys were disabled on 25 June 2024 and cannot be used to obtain a new key. Keys issued before that and not revoked still work (https://dev.vk.com/en/api/access-token/getting-started). An old unrevoked stories key is the key that will not expire hourly.
   - `stories.get` still names a standalone Implicit Flow token and `VKWebAppGetAuthToken` in a mini app. That event’s scope list includes `stories` (“доступ к историям, созданным пользователем”) and the result includes an `expires` time. It runs inside the mini app, not in GitHub Actions (https://dev.vk.com/ru/bridge/VKWebAppGetAuthToken).
   - Error 5 is “Авторизация пользователя не удалась” (check the auth scheme). Error 15 is “Доступ запрещён” (check the ids, and that this user can open the content on the full site). Error 17 is “Требуется валидация пользователя”; VK says to redirect the user to its validation page (https://dev.vk.com/ru/reference/errors). This sync does not redirect and does not retry.
   - Until the business profile is verified, a new user gets 10,000 VK API calls a month, then 100,000,000. Those limits take effect on 7 September 2026. Authorization through VK ID is not counted.

add it as the repo secret VK_USER_TOKEN in GitHub Settings > Secrets and variables > Actions.
